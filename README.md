# Notes App

A modern notes app built with **Flutter**, **GetX** and **Cloud Firestore**, featuring a soft glassmorphism UI, live search, category and date filters, and real-time sync.

## Features

- **Create, read, update and delete** notes with real-time sync through Cloud Firestore
- **Live search** with a 300 ms debounce
- **Category filters** (Personal, Work, Ideas, Important) and **date-range filters** (Today, Last 7 days, Last 30 days)
- **List and grid layouts**, switchable with one tap
- **Delete with undo**: a confirmation dialog, then an undo snackbar
- **One form for create and edit**, with validation and a character counter
- **Glassmorphism design** with a soft light palette, backdrop blur and micro-animations (Hero transitions, staggered list entry, skeleton loading)
- **Polished states**: loading skeletons, empty state, no-results state and an error state with retry
- **Responsive** layout (grid columns adapt to the screen width)

## Architecture

Controllers depend on a repository **interface**, not on Firebase, so the backend can be swapped or mocked in tests.

```
lib/
├── main.dart
├── firebase_options.dart            # generated by `flutterfire configure`
├── app/
│   ├── app.dart                     # root GetMaterialApp
│   └── routes/                      # app_routes.dart, app_pages.dart
├── bindings/                        # initial, home, note_detail, note_form
├── controllers/                     # splash, home, note_detail, note_form
├── core/
│   ├── constants/                   # app_colors, app_sizes, app_strings,
│   │                                # app_durations, app_assets, firestore_constants
│   ├── responsive/                  # responsive.dart (screen-size helpers)
│   ├── theme/                       # app_theme, app_text_theme, glass_theme
│   └── utils/                       # app_snackbar, date_formatter, validators
├── data/
│   ├── models/                      # note_model, note_category
│   ├── repositories/                # note_repository (interface)
│   └── services/                    # note_service (Firestore implementation)
└── views/
    ├── ui/                          # splash, home, note_detail, note_form screens
    └── widgets/                     # glass_card, glass_icon_button, app_button,
                                     # custom_text_field, search_bar_field,
                                     # filter_chip_group, category_badge, note_tile,
                                     # animated_list_item, gradient_background,
                                     # loading_view, empty_state_view, error_state_view
```

### Design rules followed

- **No hardcoded values in widgets**: every color, string, size and duration lives in `core/constants` or `core/theme`.
- **Small views**: UI is split into reusable custom widgets.
- **Performance**: backdrop blur is lowered in lists, tiles are isolated with `RepaintBoundary`, and duplicate Firestore updates are skipped.

## Data model

Collection: `notes`

| Field | Type | Notes |
|---|---|---|
| `title` | string | 1 to 100 characters |
| `content` | string | 1 to 5000 characters |
| `category` | string | `personal`, `work`, `ideas` or `important` |
| `createdAt` | timestamp | set by the server, never changed |
| `updatedAt` | timestamp | set by the server on every edit |

## Getting started

### Prerequisites

- Flutter SDK (stable) and Dart 3
- A Firebase project with Cloud Firestore enabled
- Node.js (for the Firebase CLI)

### 1. Install dependencies

```bash
flutter pub get
```

### 2. Connect Firebase

```bash
npm install -g firebase-tools
dart pub global activate flutterfire_cli
firebase login
flutterfire configure --project=<your-project-id> --platforms=android,web
```

This generates `lib/firebase_options.dart` for your own Firebase project.

### 3. Create the database and publish the rules

```bash
firebase init firestore     # choose your project; keep the existing firestore.rules
firebase deploy --only firestore:rules
```

### 4. Run

```bash
flutter run -d chrome
```

The app has been tested on Chrome (web).

## Known limitations

- **No authentication.** The database is a single public collection for demo purposes, and the security rules validate the shape of the data only. Do not use it with real user data before adding authentication.
- On the web, Firestore offline persistence is not enabled by default.
- The UI is English only.
